## 怎么读这张图

- 纵向是时间，每个阶段一张卡片；左侧是日期与阶段编号，右侧是这一阶段新增的插件/能力。
- 卡片里的 chip 是**插件包名或能力名**，不是一次提交；一个阶段内可以有多次提交。
- 底部红色虚线卡片是**已设计但尚未落地**的下一步，不属于已完成的时间线。
- 10-26 之后用强调色标出：项目从"能跑"转向"边界可解释、过程可读、知识可治理"。

## 两个观察

1. **插件数量在四天内从 0 到 74，但分组方式一直没变**：数据/能力、Web 适配、客户端半边、执行边界。新增能力基本只是往这四类里加包。
2. **越晚的阶段越"可治理"**：前两阶段解决"能不能做"，中间解决"过程能不能解释"，最后解决"知识怎么沉淀、自动操作怎么设边界"。沙箱面板、轨迹、知识库审核都属于后一类——它们不是新能力，而是让已有能力可被信任。

## 维护

时间尺按阶段而非提交更新。新增一个阶段时：

1. 在 SVG 里加一张卡片（复制现有 `<g>`，改日期、标题、chip）；
2. 同步上面的阶段表；
3. 如果新增的是"已设计未落地"，放进虚线卡片，不要放进正常时间线。

需要重新排版时，chip 宽度按字符宽度估算、每行 `CARD_W - 40` 换行即可，SVG 不依赖外部字体。
