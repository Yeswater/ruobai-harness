# 会话信息栏

右侧的会话信息面板，布局对齐 Claude Code desktop：环境 / 上下文 / 输出 / 更改，四段可折叠，所有行都能跳到真正能操作它的面板。

## 1. 布局与数据来源

| 段落 | 内容 | 数据来源 |
| --- | --- | --- |
| 环境 | 工作区名称与路径、Git 分支与 ahead/behind、模型与模式/权限 | `session`、`GET /api/git/info` |
| 上下文 | 已用比例、占比条、消息 / MCP 工具 / 系统工具 / 系统提示 / 剩余空间，以及记忆条目与知识库页面数 | `GET /api/sessions/:id/context` |
| 输出 | 本次会话写过的文件（按路径去重，最新的在前），工具名与文件大小 | `GET /api/checkpoints/:id` 的 `file/change` 列表 |
| 更改 | 工作区未提交改动的 `+added / −removed` 汇总与文件列表 | `GET /api/git/status` |

数字与 CC 面板一致地使用紧凑格式（`193.4k / 1M`、`17.6%`），颜色沿用现有主题变量。

## 2. 联动

| 点击 | 行为 |
| --- | --- |
| 环境 → 工作区行 / 齿轮 | 打开设置（通用） |
| 环境 → 分支行 | 打开 Git 面板 |
| 上下文 → 详情 | 主区切到“上下文”视图 |
| 输出 → 某个文件 | 打开文件面板并定位到该文件 |
| 输出 → 还有 N 个 | 就地展开/收起（不改变面板） |
| 更改 → 查看全部 / 还有 N 个文件 | 主区切到“更改”视图 |
| 更改 → Git 面板 | 打开 Git 面板 |
| 更改 → 创建 PR | 提交本次会话的未提交文件并创建 PR |

文件定位通过 `FileBrowser.openPath = { path, token }` 完成：每次请求带一个新 token，组件只在 token 变化时打开一次，避免重复渲染把用户切回旧文件。

## 3. 更改视图

主区新增“更改”，左右分栏：

- **左侧**：当前筛选的文件树（按目录分组，逐文件 +/−）、下方两个筛选页签（未提交的更改 / 所有更改）、再下面是最近 6 条提交（哈希、标题、相对时间）。
  - 未提交的更改来自 `git status`；所有更改来自当前会话检查点的 `file/change` 去重列表，diff 直接用写入时保存的补丁。
- **右侧**：选中文件的 unified diff（复用 Git 面板的 `DiffPane`），会话来源标“会话改动”，工作区来源标“工作区”。
- 顶部显示当前筛选的文件数与刷新按钮；切换筛选时自动选中第一个文件。

## 4. 创建 PR

按钮出现在会话栏“更改”段落和更改视图顶部，打开一个确认对话框（标题、描述、新分支、基础分支），并明确写出“将提交当前列表中的 N 个文件”。

- 只提交**当前筛选**里、且仍有未提交改动的文件；其余暂存改动不会被卷进来（`git commit -m … -- <paths>` 走 pathspec）。
- 流程：`git checkout -b <branch>` → `git add -- <files>` → `git commit -- <files>` → `git push -u <remote> HEAD:refs/heads/<branch>` → 建 PR。
- 远程选择：优先 `origin`，否则第一个 GitHub/Gitee 远程。GitHub 走 `gh pr create`（需要已 `gh auth login`）；Gitee 走已挂载的 `@ruobai/gitee` 服务与设置里的令牌。
- 不做 force push，不 amend；推送成功但建 PR 失败时，错误会显示出来，分支已保留，可在网页端补建。
- 没有未提交改动且当前在基础分支上时直接拒绝。

## 5. 刷新策略

- 上下文与输出：会话 id、`stats` 或消息数变化时刷新；`stats` 每步都会更新，工具刚写完文件就能看到输出。
- Git：仅在回合结束（`streaming === false`）或切换会话时刷新。`git status` 会启动子进程，流式过程中反复调用不划算。
- 切换会话时四段一起重置，旧数据不会串到新会话。

## 6. 边界

- **默认只读**：浏览、筛选、看 diff 都不写文件；唯一会改变仓库的是用户点击“创建 PR”并在对话框里确认——它提交、推送并建 PR，文件范围就是当前筛选里仍未提交的部分。
- **输出只覆盖工具写入**：来源是检查点的 `file/change`，也就是 `write_file` / `edit_file`；通过 `bash` 里 `sed -i`、`python` 脚本改的文件不会出现在“输出”，但会出现在“更改”（Git 视角）。
- **PR 只支持 GitHub `gh` 与 Gitee API**：其他托管平台会得到明确的错误；没有 `gh`/令牌时不会尝试推送。
- 面板宽度沿用右侧 DetailsPanel，可拖拽、可展开；窄屏下与文件/Git 面板共享同一套收起逻辑。

## 7. 验证

- 浏览器实测：环境显示工作区、`main`、模型；上下文显示 `已使用 18% · 193.4k / 1M` 与五段占比；输出列出 19 个 `tmp-cdp/*.mjs` 并能在点击后打开对应文件；更改显示 `+5494 −3853 · 53 个文件`。
- 联动实测：`详情` 把主区切到“上下文”；`Git 面板` 把右栏切到 Git；输出行打开文件面板并激活对应标签。
- 更改视图实测：未提交 60 个文件、diff 33 行、提交 6 条；切到“所有更改”为 19 个文件（检查点），diff 80 行；PR 对话框显示“将提交当前列表中的 17 个文件”。
- `packages/git/tests/pr.spec.ts`：非法分支/越界路径被拒；基础分支且无选中改动被拒；无远程时在推送前失败，并验证提交只包含选中的路径、其他暂存文件保持不变。
- 全量 `pnpm test` 通过，`typecheck` 与 `build:ui` 通过。
