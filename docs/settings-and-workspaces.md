# 设置面板与左侧功能区的重构

## 问题

设置面板原本是一个纵向表单：字段直接铺在页面上，说明文字跟在字段下方，页面之间靠页签切换。设置项变多后出现三个问题：

1. **扫读成本高**。标签、控件、帮助文字在同一列里交替出现，视线要上下跳。
2. **功能位置不对**。知识库、MCP 连接器、技能都藏在设置里，而它们是日常使用的入口，不是一次性配置。
3. **页面实现集中**。`SettingsDialog.tsx` 同时管理供应商草稿、主题、插件运行时和路由，930 行里混着五种状态。

WorkBuddy 的设置面板提供了参照：左侧分组导航，右侧一列卡片；每张卡片里一行一个设置项，左边标题与说明、右边控件。它的「资料库」则是独立的三栏工作区：页面列表、正文、目录。

## 约束

- 不改变任何后端接口。设置、供应商、审批、MCP、技能、Wiki 全部沿用现有 REST。
- 插件页仍然通过 Slot 组合；宿主不能 import 插件实现。
- 不引入新依赖。Markdown 渲染复用已有的 `react-markdown`。
- 浅色/深色两套主题必须同时成立；不能用固定色值。
- 浏览器端不 fold 领域数据；知识库页面列表、正文、目录都来自 `/api/wiki` 的窄快照。

## 方案

### 设置面板

- `components/settings/SettingsDialog.tsx` 只负责导航、搜索与页面分发。每个页签带一句描述，显示在标题下方。
- `components/settings/SettingsLayout.tsx` 提供三个原语：
  - `SettingsScroll`：内容滚动区；
  - `SettingsGroup`：带组标题的卡片容器；
  - `SettingRow`：左侧标题/说明、右侧控件的横排。
- 通用页重写为三组卡片：外观、新建会话、上下文。底部是保存栏，显示「有未保存的更改」并只在脏状态启用保存按钮。
- 供应商页保留左右两栏，但右栏变成带分区标题的卡片；模型编辑卡片嵌在「模型」分区里。
- 内置插件页从卡片网格改成行列表：名称、状态、说明、ID 与服务、右侧开关。

### 左侧功能区

`Sidebar` 顶部新增 `function-rail`，两个入口：

| 入口 | 目标 |
| --- | --- |
| 知识库 | `KnowledgeWorkspace`，三栏资料库 |
| 专家·技能·连接器 | `ToolsWorkspace`，顶部三个页签 |

`ToolsWorkspace` 参考 WorkBuddy 的技能页：顶部是「专家 / 技能 / 连接器」页签，右侧是 SkillHub 搜索。

布局自上而下固定为：品牌行（右上角「新建」与收起按钮）→ 功能轨道 → 「工作区」标题行（搜索、视图筛选、添加工作区）→ 会话列表。功能入口在筛选之上，避免把临时功能区和会话治理混在一起。

- **新建**：左上角按钮打开工作区选择对话框（⌘N 同）。选中的文件夹成为会话的根。
- **空会话复用**：当前会话还没有任何消息、且要选的文件夹与它相同时，对话框直接回到这个会话，不新建第二个空行。
- **空会话界面**：输入之前主区只保留菜单按钮——标题、会话/轨迹/上下文页签、搜索与工具按钮都隐藏，正文是一张过去一年的贡献度图（每格一天，按当天用户消息计数，中文文案），数据来自 `GET /api/activity`。
- **会话记忆**：当前会话 id 写入 `rbh-active-session`，刷新后回到同一个会话，没有消息的空会话也一样；实时通道重连时重新拉取 `/api/sessions`，补齐离线期间新建或删除的会话。

- **技能**：精选技能、分类与排序、SkillHub 卡片网格、已安装技能、待审提案。
- **连接器**：直接复用 `McpSettings`。
- **专家**：规划中占位，说明专家会打包提示词、技能与连接器。

点击会话会清空功能视图并回到对话；主区标题栏显示功能名、描述与「返回会话」。⌘K 面板的 `wiki` / `skills` / `experts` / `connectors` 分别打开对应工作区与页签。

### SkillHub

技能页连接 `https://api.skillhub.cn`：服务端代理列表、分类与精选接口，避免浏览器 CORS；安装由服务端下载 zip 并解压到 `<workspace>/.ruobai/skills/<name>`。安装器有独立的安全边界，见 `docs/skillhub.md`。已安装的项目技能支持在工作区内移除。

### 其他面板

- **长期记忆**：统计卡（有效条目 / 注入预算 / 全局与项目）、添加卡片、检索与记忆行。`memory-web` 的客户端半边重写，但接口不变。
- **知识库设置**：设置新增「知识库」页，放「每轮自动检索」「会话空闲后生成提案」两个开关，默认关闭；知识库工作区只保留业务操作。
- **沙箱**：新增全局「沙箱保护」开关，写 `settings.sandbox.enabled`；关闭后 `shell-sandboxed` 按配置委托给 `direct` 执行器，审批仍然生效。
- **输入框**：模式选择旁新增「知识库」按钮，打开页面选择器；选中页面后把 Markdown 正文作为附件加入本条消息，不修改草稿文本。
- **权限**：内置危险命令清单展开后限制在 124px 高度内滚动，规则编辑器不再被挤出视口。

### 知识库界面

左栏是策展与治理入口，固定三视图：

- **页面**：状态筛选（全部 / 就绪 / 需复核 / 草稿）、标签筛选、标题 + 摘要 + 状态/置信度/来源状态；「需复核」包含 stale、未溯源与低置信。
- **提案**：模型生成的页面变更；接受前不修改页面。
- **目录**：管理 `index.md` 的分组与条目。可以新建目录、把页面加入某个目录或未分组、移出条目；加入后孤儿页检查立即消失。
- **检查**：按 `wiki_lint` 的 kind 分组（断链、孤儿页、缺摘要、来源过期、重名），每条可跳到对应页面。

检索始终在左栏顶部；命中结果展示 `页面 › 标题` 与 L0 摘要/片段，点击打开页面并滚动到对应小节。

中栏按模式切换：

- **阅读**：状态、置信度、所属目录、冲突标记、来源清单（文件 / 会话 / URL，带 hash 与过期标记）、正文、反链、版本；页面头部可直接加入或移出目录。
- **编辑**：标题、标签、正文；提示摘要是检索结果的 L0。
- **提案审查**：默认显示正文 diff，可切「完整提案」；元数据变化（标题、标签）单独列出；支持拒绝、接受、编辑后接受。提案 diff 只比较正文，避免时间戳噪声。
- **版本**：点击历史版本查看只读文本，可与当前版本对比；右侧目录用 `IntersectionObserver` 高亮当前小节。

`wiki-web` 新增提案详情、提案编辑与「对当前版本 diff」接口；提案正文编辑不会触碰页面，接受才写入并保留旧版本。`wiki-web` 的客户端半边仍被移除，界面属于宿主工作区。

#### 视觉规范

三栏各自承担一种职责，样式不再按面板各写一套：**侧栏是策展台**（密、轻、可扫读），**中栏是阅读器**（单一焦点、固定 measure），**右侧是导航**（无卡片、竖线指示）。

- **尺寸**：侧栏 `minmax(272px, 300px)`；正文 measure `--kb-measure: 40rem`（中文约 40 字/行）；目录列 `216px`，栏间 `48px`；标题 30px/600/-.02em，正文 15px/1.8。
- **层级只用三种手段**：字重、间距、淡底（`--tool-bg` / `--accent-soft`）。`--accent` 只给主操作按钮与「当前项」的 2px 竖条，不给普通标签。
- **当前项统一表达**：侧栏页面项与目录项都是「surface + 2px accent 竖条」，不再分别用白底、`--accent-soft` 填充。
- **状态用圆点 + 词**：`.kb-status` / `.kb-confidence` 的 `::before` 是 6px 圆点（ready `--ok`、stale/冲突/低置信 `--warn`、draft `--faint`），不再叠 pill 底色。
- **文档头两行**：主行是状态、置信度、版本、日期、冲突标记；次行是页 id（mono）、目录归属与「加入/移出目录」、标签。标题与首段之间只有一条 72% 淡分隔。
- **正文排版限定在 `.kb-doc` 作用域**：`.file-markdown` 同时服务文件预览与聊天，所以字号、`h2` 去 hairline、段落节奏都必须带 `.kb-doc` 前缀，否则会改到别处。
- **目录是 rail 不是 card**：`.kb-toc` 只有左侧 1px 竖线，`active` 用 2px accent 竖条 + 600 字重；`< 1180px` 隐藏并把正文收成单列。
- **加载态**：`data === null && !error` 时侧栏与文档列都显示 `.kb-skeleton` 微光骨架，`prefers-reduced-motion` 下静止，避免首屏闪一下空态。
- **治理入口收敛**：左栏只保留「新建页面」一个主操作，「检查」是视图页签（不是第二个按钮），空态文案负责让用户知道它的存在。

## 失败模式

- **设置加载失败**：标题栏仍渲染，正文上方显示错误；供应商页显示 loading 而不是空表单。
- **知识库接口失败**：错误显示在文档栏，不清空已加载的页面列表。
- **样式作用域泄漏**：`.file-markdown` 同时服务文件预览与聊天；正文排版改动必须带 `.kb-doc` 前缀，否则会连文件的标题线、行距一起改掉。同理 `.kb-view` 上的 `--kb-measure` 等变量只在该子树内生效。
- **目录与滚动失去同步**：`IntersectionObserver` 以 `.kb-doc-scroll` 为滚动根、以 `contentRef` 内的 `h2/h3` 为目标；把 `ref` 挪到内层或改掉滚动容器都会让高亮与跳转静默失效。
- **标题重复**：Markdown 标题 id 可能重复，目录会跳到第一个同名标题；对知识库页面来说可接受。
- **切换页签丢草稿**：通用页与供应商页的未保存修改在切页时丢弃。这与旧面板关闭后丢弃一致，但旧面板切页时会保留；目前没有做离开确认。
- **知识库提案过期**：审阅期间页面可能被另一处修改；接受仍按提案正文覆盖，旧版本保留在历史中，必要时先对比再接受。
- **自动检索未命中或超时**：只跳过本轮注入，不影响回合；结果写 `wiki/recalled`，可从轨迹排查。
- **自动提案没有模型**：provider 为 mock 或未配置时不生成；开启开关只代表允许，不代表一定会产出提案。
- **自动提案的定时器只在进程内**：重启应用或归档会话不会补触发；下一次 turn-end 之后重新计时。
- **无会话**：SkillHub 安装与技能提案按钮禁用，因为两者都需要工作区根目录；技能目录仍可浏览。
- **SkillHub 离线或被限流**：技能页显示错误和「刷新」，已安装技能与提案仍可用。
- **沙箱关闭但没有直连执行器**：设置接口拒绝关闭（409）；运行期缺执行器则 fail-closed。

## 验证

- `pnpm typecheck`：两套 tsconfig 通过。
- `pnpm test`：全量通过（新增 `markdownHeadingId` 单测）；memory-distill 偶发一条时序抖动，单独重跑通过。
- `pnpm build:ui`：浏览器产物构建通过。
- 知识库排版重做后的验证：`pnpm typecheck` 两套 tsconfig 通过；`pnpm build:ui` 通过；`pnpm test` 599 条通过（`memory-distill` 的 `commits extracted rules after an idle boundary` 在高并发下会抖动 —— 基线代码同负载偶发、单独重跑必过，与本改动无关）。
- 浏览器手测：新建知识库页面 → 保存 → 正文与目录出现；页面筛选与检索命中；提案 diff / 完整提案 / 编辑后接受；检查分组与跳页；目录分组与加入/移出；设置里的两个自动化开关；来源清单与目录归属；版本与当前对比；设置通用页脏状态与保存按钮；模型/权限/内置插件页布局；权限内置规则展开后仍能看到规则编辑器；合并后的专家/技能/连接器页签；SkillHub 卡片、分类与搜索；知识库附件；内存面板卡片；沙箱开关与关闭态提示；深色模式读取计算后的背景色符合预期。
- SkillHub 安装实测：下载 `linkding` 包 → 解压出 4 个文件（含 `scripts/`）→ 出现在 `/api/skills` → 移除后缓存失效。
